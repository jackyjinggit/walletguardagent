# P2 技术架构设计 v1.0

## 目标

通用采购协作：协助记账（合规）+ 协助决策（多人协作 + 审计追溯）+ 最后静态跳转到 Monad 链上页面。

## 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 原生 HTML / CSS / JavaScript（`dist/`） | 聊天首页 + 预算摘要 + 详情抽屉，无构建依赖 |
| 本地服务 | Node.js（`server.mjs`） | 静态托管 `dist/` + 聊天桥接 |
| 链上 | Solidity（Monad 测试网） | 采购订单合约 + 多签 + 记账事件 |
| 后端 / 数据 | Python / Go | 采购数据接入 + AI 推理 + 报告 |
| 模型桥接 | DSH Harness ACP | 本地聊天能力接入 |

## 模块划分

```
walletguardagent/
├── dist/                     # 前端产物（可直接静态托管）
│   ├── index.html            # 聊天首页
│   ├── app.js                # 前端逻辑（预算 / 订单 / 对话）
│   └── styles.css            # 样式
├── server.mjs                # 本地 Node 服务
├── docs/                     # 项目文档
├── package.json              # 启动脚本与项目元信息
└── README.md                 # 项目入口
```

- 前端负责：采购录入界面 / 审批流 / 账本展示 / 链上跳转入口。
- 服务负责：托管前端 +  `/api/health` 与 `/api/chat` 两个接口。
- 链上负责：采购订单合约 / 多签 / 记账事件与决策 hash 上链。
- 后端负责：采购数据接入 / AI 推理 / 签名代发 / 事件订阅 / 报告与异常检测。

## 数据流

1. 用户在 `dist/` 前端录入采购申请或发起对话。
2. 前端调用本地服务 `/api/chat` 或直接提交预算 / 订单状态。
3. 服务端（或后端）做合规校验与决策建议。
4. 链上部分（合约 / 记账 / 多签）由 Solidity 模块处理，最终写入 Monad 测试网。
5. 前端展示结果，并在需要时跳转到 Monad 链上页面（explorer 链接）。

## 当前状态（2026-10-16）

- 本地原型：前端 `dist/` + `server.mjs` 已就位，可 `npm start` 启动（<http://127.0.0.1:4173>）。
- 链上部分：采购付款、链上操作、报告交付**均为模拟**。
- 这**不代表** WalletConnect、多签或审计能力已完成。

## 边界

- 本地服务仅监听 `127.0.0.1`，只处理本地请求。
- 链上交互在演示阶段为模拟；真实部署为后续阶段。
- 范围不绑定特定单位类型（泛化）。
